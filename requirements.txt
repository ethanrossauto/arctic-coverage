# listed psycopg and this file did not, the build reported "Resolved 11 packages" (exactly
# the set below with its transitive deps, and no psycopg), and every route in the deployed
# app then returned 500 with ModuleNotFoundError at import time.
#
# So the two files have different jobs and BOTH have to be right:
#   requirements.txt  what the deployed function gets
#   pyproject.toml    the interpreter version, the Vercel entrypoint, and local tooling
#
# ⚠️ python-dotenv is deliberately absent. Only scripts/ reads .env.local; nothing under
# api/ imports it, and the runtime bundle should not carry what it never calls.
#

# imported lazily inside the functions that use them, so a missing one degrades to
# "that layer is unavailable" instead of crashing the app. That soft failure is correct
# behaviour and it is also very good at hiding this exact mistake: `anthropic` was
# absent from both manifests for the whole life of the reasoning layer, so tier 2 could
# never have answered anything, anywhere, and reported itself merely "unavailable".
